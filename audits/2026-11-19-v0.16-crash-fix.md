# Audit · v0.16 · the crash after linking, and the restart loop

- **Date:** 2026-11-19
- **Evidence:** the owner's problem report from v0.15 (Samsung SM-P620, Android 16):
  - `link: paired`, then 1 s later `CRASH on pool-4-thread-1: org.json.JSONException: Value null … cannot be converted to JSONArray` from the contact loader;
  - then `RuntimeException: Unable to start service app.oie.data.LinkService … ForegroundServiceStartNotAllowedException` at `startForeground`.
- **Process:** the owner's rule (design, develop, audit, fix, docs, ship). Skills: ux-user-flows and less-is-more (loaded as skills this session), impeccable `audit.native.md` and `android.md`, graphic-design-fundamentals §13.

## Root causes
1. **The crash after linking:**
   - Right after pairing there are no contacts and no groups yet, and Go's `json.Marshal` of a nil slice gives `null`. The app did `JSONArray("null")` on a background thread with no catch, and the whole process died.
   - The crash fell in the middle of the pairing handshake, so WhatsApp removed the half-linked device. That's the "disappeared from Dispositivos conectados". It hit every new link, whatever was being sent, which matches "not only images".
2. **The loop:** after the crash, Android restarted the `START_STICKY` service from the background, and Android 12+ forbids `startForeground` from the background, so the app crashed again.

## Fixes
| Fix | Where | Test |
|---|---|---|
| An empty list is `[]`, never `null` | `link/encodeContacts` | `TestNoContactsIsAnEmptyListNotNull` |
| Anything that isn't a list reads as empty | `logic/ContactsJson` | `ContactsJsonTest` |
| Every link background task catches and reports its error | `RealLink.bg {}` | Code review; the report shows "background error" lines |
| Android refusing a background start stops the service quietly; it starts when Oiê opens | `LinkService.onStartCommand` | Code review; the report shows a "service:" line |

## ux-user-flows
