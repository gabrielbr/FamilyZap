# Audit · v0.23 · photos refused, and WhatsApp's storage errors

- **Date:** 2026-11-19
- **Trigger:** the owner's report.
  - Every photo, from the camera or the gallery, showed "Não deu para abrir essa foto. Tente outra." (a photo of the screen).
  - Issue #34, the problem report from 0.21.0, showed `disk I/O error (6410)` twice from WhatsApp's store.
- **Process:** the owner's rule.
  - Design first: `docs/flows/kid-sends-message.md` (v0.23) and `docs/whatsapp-link.md` (temporary files).
  - Develop, with tests:
    - `PhotosKeepTest`, 4 tests on real JPEG files. 3 of them fail on the old code (shown before the fix);
    - Go `TestTheStoreKeepsTemporaryTablesInMemory`.
  - Audit with the four skills (loaded and read this session).
  - Then docs and ship.
- **Screens:** none change. The screenshot suite passes unchanged. What changes is that the photo preview and send now happen on a real tablet.

## Causes
1. **Photos (since v0.1):** `Photos.keep` read the size with `inJustDecodeBounds`, where `decodeStream` returns null by design. The `?: return null` after it fired every time, so no photo was ever accepted on a device. The screenshot tests used sample photos and never ran this path.
2. **Storage:** SQLite (modernc, pure Go) looks for a temporary folder in `TMPDIR`, `/var/tmp`, `/usr/tmp`, `/tmp` and `.`, and Android has none of them. A large write needed a temp file and failed with `SQLITE_IOERR_GETTEMPPATH` (6410). Fixed with `temp_store(2)`: temporary tables go in memory.

## Also fixed in passing
- **Camera photos sideways:** the turn lives in EXIF, and Oiê drops the metadata on re-encoding (for privacy), so photos would have arrived sideways. The turn is now applied first (tested).
- **The problem report** now records why a photo was refused (its type or the error), with no names and no picture.

## ux-user-flows
- **#9 Help users recover from errors:** the error showed for every photo, so it was a false message. The kid can't recover from that, and it's the peak frustration point of the send flow. Now the message shows only when a file really isn't a picture.
