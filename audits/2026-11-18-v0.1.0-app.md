## Addendum · photo sending and saving on the tablet, 2026-11-18
- **ux-user-flows** ("Kid sends a message", step 3c and branches):
  - Camera or Galeria, the last one first (Remembers).
  - A preview with Trocar and Enviar; back drops the photo; undo returns to the preview.
  - A photo that can't be read shows "Não deu para abrir essa foto. Tente outra."
  - The permission branch from the flow doesn't arise: the system photo picker and the camera app need no permission from Oiê.
  - Setup resumes at the same step after closing (flow "Parent setup + link": "returning mid-setup").
- **impeccable:** photos are downscaled before display (no full-size decode); state saves happen off the main thread. Accessibility: the photo button, the sheet options and the preview image are labelled. Score unchanged (15/20); A-2 is fixed.
- **Privacy (product law):**
  - State is sealed with AES-GCM under a key kept in the Android Keystore.
  - Photos live in the app's private storage and are re-encoded, which removes location metadata.
  - The FileProvider shares only the camera's one temporary file.
  - Backup is off (`allowBackup=false`), so nothing leaves through cloud backup.
  - **Open:** encrypt the photo files themselves (P3).
- **graphic-design-fundamentals:** the photo in the chat sits in the kid's soft-coral bubble, with "Enviada" under the latest message on the right.
- **less-is-more:** the source sheet has two choices and no extra text; no confirm before sending a photo (undo instead).
- **Fixed on the first look:**
  - "Enviada" was on the left, now under the message;
  - the screenshots used the real clock, so CI failed on them (now a pinned clock and time zone);
  - the camera link was built before it was needed, which crashed in tests (now built on tap).

## Addendum · v0.3 (self-update, release workflow, portrait), 2026-11-18
- **ux-user-flows** (the design system's self-update flow):
  - Entry: a foreground check (15 min, ETag) or the manual "Procurar atualizações".
  - The sheet: Atualizar · {tamanho} / Mais tarde. During the download it shows a progress line and Cancelar; Back and taps outside do nothing. Then Android's confirmation.
  - Honest failures: couldn't check, download failed, checksum, signature. A debug copy says it can't update.
  - **Proposed difference:** the sheet shows **only in the parent area**, because the person opening Oiê is usually the kid, and an update is the parent's decision. If the owner agrees, it goes into the design system's `docs/divergences.md`. Until then it's marked proposed.
- **impeccable:**
  - Network and file work run off the main thread; one download at a time.
  - Every install check from the spec is enforced: HTTPS, complete, SHA-256 against SHA256SUMS, same package and signer.
  - Portrait checked for the kid home, conversation and parent area: the layouts wrap correctly.
  - Score 15/20 (adaptivity improves once multi-window is checked).
- **Product law:**
  - The only network use is the update check and download; nothing about the family is sent.
  - The new permissions are listed and explained in the manifest.
- **graphic-design-fundamentals and less-is-more:**
  - The sheet has one coral action (Atualizar).
  - The release notes scroll inside the sheet.
  - The version and update row sit at the bottom of Ajuda e sobre: weekly or rarer, so not on any main screen.
- **anti-slop:** the words come from the design system's table, in both languages.
- **Found and fixed:** lint caught the signer check using an Android 9 API on an app that supports Android 8, which would have crashed on 8 and 8.1. It now uses the older signatures field there, and compares SHA-256 digests of the certificates.
- **Open:** the owner's signing secrets and a public releases repo; confirming the parent-area-only sheet; multi-window.
