## ux-user-flows
- **Visibility (#1):** "Fica assim no WhatsApp:" shows the result as WhatsApp will render it, with the name in bold. The parent never has to send a test message to see it.
- **Error prevention (#5):**
  - only the first emoji is kept, and a letter is ignored, so nothing but an emoji can end up before the name;
  - a star in the name is dropped, so the bold can't break.
- **Control:** clearing the field goes back to the bold name alone. It's optional.
- **Rule unaffected:** the message rule reads the family's replies, not the kid's signature.

## impeccable · native audit
- **Accessibility:**
  - the field has a label and help;
  - the preview is plain text that TalkBack reads ("Tito: Oi, vó"), with the bold as style only;
  - the emoji comes from the system's own emoji font.
- **Theming:** the preview sits on `surface`, like a message, with tokens only; checked in dark (28).
- **Score:** 16/20, unchanged.

## graphic-design-fundamentals §13
- **Hierarchy:** the preview is the one element in body size after the captions, so the eye lands on the result.
- **Typography:**
  - bold for the name only, the same emphasis WhatsApp will give;
  - one family (Nunito);
  - the emoji is the parent's content in the system emoji font, not part of Oiê's type.
- **Brand rule "no emoji in UI text":** kept. Oiê's own copy has no emoji. The field shows only what the parent picked, and the preview shows the parent's own content.
