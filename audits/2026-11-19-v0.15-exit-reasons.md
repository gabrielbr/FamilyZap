# Audit · v0.15 · catching the exits the app can't see

- **Date:** 2026-11-19
- **Trigger:** the owner's report. Oiê went back to the tablet's home screen with no crash message, Oiê disappeared from WhatsApp's Dispositivos conectados, and the connection problem happens with text too, not only photos.
- **Process:** the owner's rule (design, develop, audit, fix, docs, ship). Skills: ux-user-flows and less-is-more (loaded as skills this session), impeccable `audit.native.md` and `android.md`, graphic-design-fundamentals §13.

## Reasoning
- A Kotlin crash shows Android's "Oiê parou" message; this exit didn't. That points to an exit outside the app's own code:
  - a Go fatal error in the WhatsApp library;
  - a native crash;
  - Android ending the process (low memory while the camera is open is a classic case).
- The v0.14 crash handler catches none of these. So v0.15 adds the two sources that do:
  - Go's own crash output, written to a file;
  - Android's exit records (API 30+).
- **Being removed from Dispositivos conectados** is WhatsApp unlinking the device (a `LoggedOut` event with a reason code, already in the v0.14 report). Its cause can't be inferred without that code. No fix is guessed: the owner's next report decides the fix.

## less-is-more
Nothing is added on screen. Low-memory, native-crash and not-responding exits count as "Oiê fechou sozinho", so the parent sees one line, not a list of codes; the codes stay in the report.

## Privacy
- **Go crash output:** it holds stack traces only, never message content.
- **Exit records:** a reason, a description and memory use.
- Both go through the same masking, and stay on the tablet.
