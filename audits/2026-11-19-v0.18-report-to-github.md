- **Screens:** 19 (tablet, after a crash), p11 (phone, 1.3× text).

## Decision: open GitHub's form, don't upload from the app
- **A direct upload would need a GitHub token inside the app.** Anyone with the APK can pull it out and file or read issues in the owner's private repo. That's a security hole, so it's not done.
- **Product law:** nothing about the family leaves the tablet by itself. With GitHub's own new-issue page, filled in and opened in the browser, the parent sees exactly what goes and sends it as themselves.
- **Size:** web addresses have a limit. The body is capped at 6,000 encoded characters; the newest lines are kept, and the issue says the full report can still be copied (tested).

## ux-user-flows
- **Fewer steps:**
  - before: copy, open GitHub, find the repo, new issue, paste, title, submit;
  - now: one tap in Oiê, then Submit in GitHub.
- **Control:** the parent reviews before sending; Copiar stays for anyone without access to the repo.
- **Errors:** with no browser, nothing happens and nothing crashes (`runCatching`). P3: it could say so; very rare on Android.

## impeccable · native audit
- **Conformance:** an `ACTION_VIEW` intent to the system browser, the platform way to hand off to the web.
- **Accessibility:** buttons with words, 48dp, and they wrap on a phone (checked at 1.3×).
- **Score:** unchanged at 16/20.
