# Audit · v0.46.0 · groups as groups, and reacting to any media

- **Date:** 2026-11-21
- **The owner:**
  - "a group is a group … show all the content that happens in a group, but people that are not on their list should have a visual flag";
  - "the messages don't bring who sent them … we must have the names of people";
  - "allow the kids to react to messages received or any type of media … tap, hold and select some emojis."
- **What changed:**
  - **The link:** `link.go` sends `senderAlt` and `senderName` for group messages (tested).
  - **The rule:** `MessageRule` shows every message in an allowed group (tested).
  - **The gate:** `RealInbox` passes the parent's own messages in a group as `fromParent`. The kid's echoes are never shown twice (tested).
  - **New logic:** `GroupSender` (tested). `Message` gains `senderAlt`, `senderName` and `fromParent`, all saved.
  - **The conversation:** a `SenderLine` (the name once per run, "Fora dos contatos" for outsiders). Photos, videos, GIFs and voice use `combinedClickable`, so a long press reacts (UI test `ReactOnMediaTest`; it failed before the fix on a photo and passes after).
  - **Home and notifications:** the preview and the notification start with "Vovó: …".
  - **The group's editor:** says what the kid sees, instead of the kid-only switch.
  - **Copy:** Ajuda and the group note.
  - **Docs:** the product law reworded in AGENTS.md and PRODUCT.md; decision 0016.
- **Research:** the conventions of WhatsApp, Telegram and Signal (sender name once per run, unknown senders by profile name, long press for reactions on any message). They're written up in the flow; no web search was needed, as these are stable, well-known patterns.
- **Skills used and how:** all four were loaded and read in this session. `ux-user-flows` wrote `docs/flows/groups.md`. The others were run on `79-group-chat` (light and dark), phone `p58` (1.3× text, a long outsider name), and the changed contacts screenshots.

## 3. graphic-design-fundamentals (§13)
- **Hierarchy ✅:** the name (label) leads its run, then the bubbles. The tag is quieter than the name.
- **Proximity ✅:** the name sits 8dp above its first bubble and further from the run before it.
- **Consistency ✅:** the outlined tag matches the app's quiet chips. The names use the same label style as the home.
